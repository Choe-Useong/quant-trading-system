# AI 협업 방식

이 프로젝트에서 사람과 AI 코딩 에이전트가 일을 어떻게 나누고, 결정과 검토를 어떻게 했는지 정리한 문서다. 작업 규칙과 검증 방법의 전체 목록은 [시스템 사용·운영 방식](system_operations.md#5-개발-방식과-품질-관리)에 있다.

## 1. 역할 분담

| 사람 | AI 코딩 에이전트(Claude Code) |
|---|---|
| 전략 아이디어 발굴과 실험 요청·설계 | 설정 파일 작성, 백테스트 실행, 결과 정리 |
| 제시된 선택지 중 채택·보류 결정 | 분석, 선택지·추천안·판단 근거 제시 |
| 코드 수정 승인 | 코드 구현, 테스트 작성·실행 |
| 프로젝트 규칙 작성, 공개 범위 등 제약 설정 | 결함 기록, 문서 갱신 |

- 작업 성격별(기획, 개발, 전략 연구, 운용 관리, 문서)로 에이전트 세션을 나누어 운영함
- 과최적화 방지 원칙(계산 전 후보와 통과 기준 사전 등록, 최고점보다 안정 구간 선호, 시점·파라미터 앙상블)은 전략 연구 세션이 제안한 것을 받아들여 연구 방식으로 사용함

## 2. 결정 방식

- 에이전트가 분석 결과와 함께 선택지, 추천안, 판단 기준을 제시하고, 사람이 그중에서 선택하거나 보류·되돌림을 결정함. 제시된 안이 맞지 않으면 근거를 다시 묻거나 다른 방향을 지시함
- 코드 수정은 에이전트가 문제점, 수정 필요성, 코드 복잡도를 먼저 보고하고 사람이 승인한 뒤 진행함
- 실험 방향은 대부분 에이전트가 제안하며, 사람은 실험을 요청하거나 설계를 바꾸고 결과의 채택 여부를 정함

## 3. 판단 사례

**실험 설계: 분위 그룹 롱숏 72개 조합**
- 거래대금과 수익률로 종목을 나눠 분석한 논문을 보고, 분위 그룹끼리 롱숏을 조합하는 실험을 설계함. 알트코인 선물의 거래대금과 수익률을 각각 3분위로 나눈 9개 그룹에서 롱 9 × 숏 8 = 72개 조합을 전부 비교함
- 최상위 조합이 이후 선물 전략의 기반이 됨. 결과는 [72개 조합 비교](strategy_examples.md#strategy-alt-futures)에 있음

**채택 보류: 이벤트 전략의 데모 운영**
- 업비트 원화 마켓 상장 종목을 선물에서 숏하는 이벤트 전략은 백테스트 성과가 기존 전략보다 좋았으나, 이벤트 수익이 최근 기간에 집중되어 있었음
- 실계좌에 바로 넣지 않고 데모 계좌에서만 운영하며, 정해 둔 이벤트 수 또는 날짜에 도달하면 전진 검증 기준으로 다시 판단하기로 함

## 4. 검토 방식과 한계

- 코드와 설정 파일은 직접 읽지 않고, 결과와 에이전트의 설명으로 검토함. 이상 징후가 있으면 추가 확인을 요청하고, 보고된 근거를 바탕으로 진행 여부를 결정함
- 계산과 운영의 오류는 여러 층의 검증으로 확인함: 자동 테스트와 손계산 사례, 독립 구현 비교, 외부 시뮬레이터(Freqtrade) 대조, 미래 정보 차단 점검, 데모 계좌와 백테스트의 비교. 방법별 내용은 [검증 방법](system_operations.md#53-검증-방법)에 있음
- 한계: 이 검증들은 정해진 규칙대로 계산했는지를 확인하며, 규칙이나 데이터가 현실과 맞는지는 따로 걸러내지 못함. 같은 에이전트가 코드와 테스트를 함께 쓰면 같은 오해가 양쪽에 들어갈 수 있음
- 사례: 국내 주식 백테스트가 거래정지 기간의 고정 가격으로 오류 없이 체결하고 있었음. 해당 종목이 상장폐지되어 계산이 중단된 뒤에야 드러났고, 거래량이 없는 날은 체결을 미루는 옵션을 엔진에 추가해 모든 국내 주식 설정에 적용함
- 선물 전략은 실계좌에 넣기 전에 데모 계좌에서 먼저 운영하며, 백테스트와 실제 운영의 차이를 추적함

## 5. 기록

- 결과·데이터·실거래 동작을 바꾸는 결함은 번호를 붙여 기록하고, 수정 후 재현 사례로 재검증해야 해결로 바꿈
- 테스트는 실제로 실행한 것만 통과·실패 수와 함께 보고함
- 새 실험은 계산 전에 가설과 통과 기준을 먼저 적고 결과를 그 아래에 붙임. 이전 결과를 무효로 만드는 오류를 발견해도 기록을 지우지 않고 정정 내용을 남김
- 전체 규칙은 [프로젝트 규칙](system_operations.md#52-프로젝트-규칙)에 있음
